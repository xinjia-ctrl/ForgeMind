# ForgeMind 产品需求文档（PRD v3.0 — 研发操作系统）

> 版本：v3.0（第九轮 — 终极形态）
> 前置：v2.0 已规划（企业集成 + RBAC + 审计）
> 状态：规划中
> 对齐愿景：E1-E5 全部，最终形态北极星

---

## 1. 产品定位（本轮视角）

v1.0-v2.0 让 ForgeMind 成为"可并行、可接入、可治理"的研发平台，但仍是**被动工具**：等人给需求、人发起 Run、人批准。v3.0 要跨过最后一道坎——从"工具"变为"**系统里主动工作的研发成员**"：

- **主动式 Agent**：不等需求，盯住 issue / CI 失败 / PR 评论，自主判断并触发研发闭环；
- **多 Agent 协商**：任务出现分歧（架构方案冲突、门禁反复驳回）时，Agent 之间结构化协商而非纯靠编排者裁决；
- **自进化**：长期记忆（L4 语义）让系统随项目演进持续变好。

这是 VISION 的终极答案：**一个真正"在研发团队里干活"的 AI 软件工程师部门**。

## 2. 目标用户与场景

| 场景         | 用户      | 核心诉求                                                          |
| ------------ | --------- | ----------------------------------------------------------------- |
| 无人值守研发 | 团队      | 新 issue 自动被认领、分析、出 PR；CI 红了 Agent 主动看为什么      |
| 复杂方案决策 | Tech Lead | 架构冲突时看到 Agent 的备选方案与协商过程，而非单向拍板           |
| 长期项目维护 | 团队      | 系统记得项目的所有上下文，新人接入成本趋近于零                    |
| 终极面试展示 | 候选人    | 展示"从闭环到操作系统"的完整演化，多 Agent 协商是顶级架构能力证明 |

## 3. 核心能力

### P0（本轮必做）

**A1 主动式 Agent（事件驱动）**

- 监听事件源（issue 创建/评论、CI 失败、PR 评论、定时巡检），生成**事件 → 任务判定**（值得做 / 需确认 / 忽略）；
- 判定值得做 → 自动走 v1.0 的 DAG 编排（复用全部能力）；
- 高风险或需人工拍板时 → 升级为审批请求，不越权执行；
- 主动性有**频率与范围上限**（每日任务配额、仅限授权仓库），防止失控。

**A2 多 Agent 协商**

- 触发点：ARCH 方案冲突、REVIEW 反复驳回（连续 N 次）、跨任务产物不一致；
- 协商协议：`Proposal → Counter → Decision` 三轮有界协商，**不是自由对话**；
- 协商产物：结构化 `decision-record`（各方立场 + 权衡 + 最终裁决），写入记忆（L3 decision），可审计可回放；
- 裁决兜底：协商超时/无共识 → 升级人类审批，不无限循环。

**A3 自进化记忆（L4 语义记忆实装）**

- v0.5 预留的 L4 接缝实装：跨任务、跨项目的语义检索（向量），补充关键词检索不足；
- 决策记录、项目约定、失败教训进入长期记忆，随协商与新 Run 持续更新。

### P1（本轮力争，可延后）

**A4 自我评估与质量回馈**

- Run 完成后对产出做质量评分（门禁通过率、返工轮次、测试覆盖率），反馈到提示词/策略；
- 形成"系统越用越懂本项目"的闭环证据（报告 + 审计）。

## 4. 关键形态决策（待评审）

| 决策点     | 方案 A                                      | 方案 B         | 建议                                                                  |
| ---------- | ------------------------------------------- | -------------- | --------------------------------------------------------------------- |
| 主动触发   | 事件订阅 + 判定器（规则 + LLM 判定）        | 纯定时轮询     | **A**：事件驱动及时且省资源，判定器有边界（白名单仓库/频率上限）      |
| 协商机制   | 有界结构化协议（Proposal→Counter→Decision） | 开放对话拓扑   | **A**：结构化协商可审计、有界、不失控；开放对话与"编排者决策"架构矛盾 |
| 自进化反馈 | 评测集扩展 + 决策记录沉淀                   | 在线学习改权重 | **A**：知识沉淀而非模型调参，可控可解释，不引入训练链路               |

## 5. 非目标（本轮不做）

- 不做全自主无人值守（关键动作永远有人类审批兜底，这是安全红线）。
- 不做开放式 Agent 自由对话（无界协商违背架构，也难审计）。
- 不做模型微调/训练链路（自进化靠知识沉淀，不靠改模型）。
- 不做跨组织通用智能（记忆边界 = 授权仓库，不透出）。

## 6. 演示验收标准（DoD）

给定一个演示环境（预先埋入 1 个新 issue + 1 个 CI 失败），必须同时满足：

- [ ] 新 issue 被主动识别并触发 Run，无需人工发起；
- [ ] CI 失败被主动分析，产出根因判断与修复 PR；
- [ ] 一次 REVIEW 反复驳回场景触发多 Agent 协商，产出结构化 `decision-record`；
- [ ] 协商无共识时升级人类审批，有界不无限循环；
- [ ] 协商决策进入长期记忆，后续 Run 可检索引用；
- [ ] 所有主动动作、协商、审批全量入审计，可逐步回放；
- [ ] 既有 61 个测试全部通过，v1.0/v2.0 能力不回归。

## 8. 风险与评审要点

1. **主动失控是最大风险**：必须三层约束——授权仓库白名单 + 每日任务配额 + 关键动作必须审批。主动不等于无监督。
2. **协商变聊天**：若协商退化为自由对话，架构与可审计性全崩。协商必须是**有界结构化协议**，超时升级。
3. **自进化不可解释**：质量回馈必须可见（报告 + 审计），禁止黑盒改行为。
4. **系统复杂度达峰**：v3.0 是所有轮次的叠加。必须严守"加外层不改内核"，否则回归风险失控。
