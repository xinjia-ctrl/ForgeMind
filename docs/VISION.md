# ForgeMind 产品愿景（VISION）

> 版本：v1.0
> 定位：所有迭代的北极星，回答"这个产品最终要成为什么"
> 状态：已评审

---

## 1. 一句话愿景

给研发团队一个"AI 软件工程师部门"——人类做产品决策与关键审批，Agent 体系做执行与质量保障。

**核心叙事**：从"最小闭环"到"企业级系统"的完整演进路线能讲清楚，这本身就是产品最大的资产。

## 3. 最终版的五个核心体验

**E1 一个需求从自然语言到上线**

```text
"给支付模块加 Stripe 支持，要求 PCI 合规"
→ 生成计划 → 架构决策 → 并行编码 → 自动审查 → 沙箱测试 →
→ 安全审批 → 合并 PR → 触发 CI → 生成发布说明
```

**E2 人机协作的审批范式**

- 常规改动：全自动，Agent 完成到 PR
- 高风险动作（改支付、动数据库、发布）：人类审批门禁
- 管理者看板：全局流水线实时可视，任何一步可暂停/介入/回滚

**E3 企业级记忆与工程资产**

- 系统记得项目约定、历史决策、失败教训（四层记忆）
- 每次 Run 是可回放、可审计、可复现的"研发档案"
- 知识沉淀为团队资产，不随人离职流失

**E4 多语言多仓库的研发舰队**

- 一个需求可拆解为多个并行 Agent 任务（前端/后端/测试）
- 跨仓库编排，统一门禁（代码审查 + 测试 + 安全扫描 + 合规检查）

**E5 可观测即信任**

- 每个 Agent 的动作、token 消耗、工具调用、审批决策全部留痕
- 面试/审计场景：一次 Run 就是一个可逐步回放的完整研发故事

## 4. 能力演进路线

| 版本             | 定位            | 里程碑能力                                                  |
| ---------------- | --------------- | ----------------------------------------------------------- |
| **v0.2**（已有） | 单任务闭环 Demo | 6 Agent 顺序流水线，门禁强制，事件可回放                    |
| **v0.5**（规划） | 智能工程        | 四层记忆、上下文工程、提示词版本化评测                      |
| **v1.0**         | 生产可用        | 沙箱隔离、审批网关、配置化策略、多仓库                      |
| **v2.0**         | 企业平台        | 并发 DAG、Web 工作台、Jira/CI 集成、权限治理                |
| **v3.0**（终极） | 研发操作系统    | 主动式 Agent（盯 issue、修 bug、回 PR 评论）、多 Agent 协商 |

## 5. 三条不变判断

1. **架构主线不变**：编排者 + 阶段化流水线 + 事件事实源。演进是"往上加层"，不是推倒重来。
2. **安全与可观测是生死线**：不是 feature，是底线。没有这两条，系统永远只是 Demo。
3. **面试叙事**：终极版的价值不是"功能多"，而是"演进路线完整且能讲清楚"。

## 6. 北极星度量（产品是否走在正轨）

- 一次 Run 的端到端成功率（需求 → 有效 commit）
- 门禁拦截的真实缺陷数（审查/测试真的在起作用）
- 二次 Run 因记忆而减少的返工轮次
- 高风险动作 100% 经过审批门禁
